# DESCRIPTION

A Pac-Man game in Python with a Looney Tunes look: Bugs Bunny (the
player) eats the pacgums and the carrots (super-pacgums) of a maze drawn
on a prairie, chased by Elmer, Taz, Marvin and Wile E. Coyote (the 4
ghosts). The 10 mazes are generated by the A-Maze-ing package of another
group. The game has a main menu, a pause menu, highscores, instructions
and a cheat mode for the review.


# INSTRUCTIONS

Python 3.10 or later is needed.

```
make install                    # create .venv and install the dependencies
make run                        # = python3 pac-man.py config.json
make debug                      # same, with pdb
make lint                       # flake8 + mypy
make package                    # build dist/pac-man (PyInstaller)
make clean / make fclean        # remove the caches / and .venv, dist
```

Packaged version: `./pac-man config.json` (the `dist/` folder contains
the game, `config.json` and this README). It is uploaded on itch.io as
an unlisted build: <link to add>.

Controls:

| Key                     | Action                                      |
| ----------------------- | ------------------------------------------- |
| Arrows, WASD or ZQSD    | move / choose in a menu                     |
| Enter                   | validate                                    |
| Space or P              | pause / resume                              |
| Esc                     | back to the menu, quit from the main menu   |
| C, then F1 to F7        | cheat mode (see below)                      |

Cheat mode (press C in game, then): F1 invincible, F2 next level,
F3 freeze the ghosts, F4 extra life, F5 speed x2, F6 ghosts always
edible, F7 only 10 seconds left. The cheats that are on are written in
red in the header. C again turns them all off.


# CONFIGURATION

`config.json` is a JSON file where the lines starting with `#` are
comments.

| Key                       | Default             | Limits     |
| ------------------------- | ------------------- | ---------- |
| `highscore_filename`      | `"highscores.json"` | not empty  |
| `lives`                   | 3                   | 1 to 99    |
| `player_speed` (cells/s)  | 6                   | 1 to 20    |
| `ghost_speed` (cells/s)   | 3                   | 1 to 20    |
| `points_per_pacgum`       | 10                  | 0 to 10000 |
| `points_per_super_pacgum` | 50                  | 0 to 10000 |
| `points_per_ghost`        | 200                 | 0 to 10000 |
| `edible_time` (s)         | 7                   | 1 to 60    |
| `ghost_respawn_time` (s)  | 5                   | 0 to 60    |
| `seed` (first level)      | 42                  | 0 or more  |
| `level_max_time` (s)      | 90                  | 10 to 999  |
| `levels`                  | 10 x `{"width": 21, "height": 13}` | at least 1 |

A value out of its limits is set to the closest limit (ex: `"lives": 0`
becomes 1). A wrong or missing value takes its default value. Unknown
keys are ignored. Each case prints a warning, then the game starts. A
missing or unreadable file prints an error and the default config is used.

Maze size: from 11 x 11 to 50 x 50. Under 11, the ghosts (in the corners)
reach Pac-Man (in the middle) in less than 2 seconds, so the player has no
time to react. The `42` is only drawn from 15 x 11.


# HIGHSCORE

The top 10 is saved in the JSON file `highscore_filename`, as a list of
`{"name": ..., "score": ...}`. It is loaded when the game starts and saved
each time a player enters a name at the end of a game (won or lost).
A missing file means no score yet; a broken file or a wrong entry is
ignored with a warning, so the game never crashes. Names keep only
letters, digits and spaces (10 characters max, "PLAYER" if empty), scores
are integers of 0 or more.

Why: a JSON file is readable, easy to check during the review, and needs
no other library.


# MAZE GENERATION

The assigned package `mazegenerator` 2.1.0 (wheel in `Ressources/`) is
installed as is by `make install`. `level.py` calls
`MazeGenerator(size=(width, height), perfect=False, seed=seed)` and reads
`generator.maze`: one number per cell, each bit is a wall (1 north, 2 east,
4 south, 8 west, 15 = closed cell of the `42`). The first level uses the
`seed` of the config, the next ones the seed 0 (random). Any error of the
generator (exception or wrong maze size) becomes a `LevelError`: the
message is shown in the main menu, without crash.

From the grid, `level.py` finds the start of the player (free cell closest
to the middle), the reachable cells (BFS), puts a carrot in each corner and
a pacgum in every other reachable cell.


# IMPLEMENTATION

- The game moves cell by cell: each character has a speed in cells per
  second, and the time since the last image (`dt`) makes it move.
- Ghosts: at each cell they take the free direction (never turning back)
  that brings them the closest to their target, counted through the
  corridors (BFS). Targets of the original game:
    - Blinky (Elmer): Pac-Man
    - Pinky (Taz): 4 cells in front of Pac-Man
    - Inky (Marvin): symmetric of Blinky around 2 cells in front of Pac-Man
    - Clyde (Coyote): Pac-Man if further than 8 cells, his corner otherwise

  They alternate 7 seconds of scatter (they go to their corner) and 20
  seconds of chase. When edible, they turn green (white when they blink)
  and run away from Pac-Man; when eaten, they go back to their corner and
  wait there as eyes for `ghost_respawn_time`.
- End of the time of a level: the player loses a life and the time
  restarts.
- Graphics: pygame, limited to the functions that have an MLX equivalent,
  as asked by the subject:

  | pygame                       | MLX                            |
  | ---------------------------- | ------------------------------ |
  | `init`, `quit`               | `mlx_init`, `mlx_destroy_display` |
  | `display.set_mode`, `set_caption` | `mlx_new_window`          |
  | `Surface`                    | `mlx_new_image`                |
  | `image.load`                 | `mlx_png_file_to_image`        |
  | `Surface.set_at` / `get_at`  | `mlx_pixel_put` / pixel of `mlx_get_data_addr` |
  | `Surface.blit`               | `mlx_put_image_to_window`      |
  | `display.flip`               | `mlx_do_sync`                  |
  | `event.get`                  | `mlx_hook` / `mlx_key_hook`    |

  So resizing, mirroring, shapes and text are done pixel by pixel
  (`font.py` is our own 5 x 7 font). The images are resized once per cell
  size and kept as lists of visible pixels. The background
  (`images/background.png`) is the prairie already resized to the window
  and darkened, so it is only loaded; the cells of the `42` show the same
  prairie without darkening (`images/background_bright.png`).
  - The game is findable on itch.io at https://limoxmo654654.itch.io/pac-man42


# GENERAL SOFTWARE ARCHITECTURE

```
pac-man.py           reads the argument, launches Application
pacgame/
  parsing.py         Config, Level: reads and checks config.json (pydantic)
  level.py           Maze: walls (mazegenerator), pacgums, BFS
  entity.py          Entity: position, direction, speed
  player.py          Player(Entity): the player
  ghost.py           Ghost(Entity) and Blinky, Pinky, Inky, Clyde
  game.py            Game: score, lives, time, levels, collisions
  cheat.py           the cheat mode (functions acting on a Game)
  highscore.py       Highscores: top 10 in a JSON file
  font.py            our pixel font
  representation.py  Images, Sprite, GameView: draws a Game
  screens.py         Application: window, main loop, menus and screens
```

`Application` owns the window, the `Highscores` and, during a game, a
`Game` and its `GameView`. `Game` creates a `Maze`, a `Player` and 4
ghosts for each level. `GameView` only reads the `Game` to draw it.
